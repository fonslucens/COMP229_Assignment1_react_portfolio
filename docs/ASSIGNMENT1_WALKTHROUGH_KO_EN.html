  • cd client: package.json이 있는 React 프로젝트 폴더로 이동합니다.

6. 코드에서 이해할 세 가지 연결

주소 → 화면

<Route path="/about" element={<About />} />

주소가 /about일 때 About 컴포넌트를 보여주는 규칙입니다. 메뉴에서 이동하는 코드는 다음과 다릅니다.

<Link to="/about">About Me</Link>

Route는 화면의 대응 관계, Link는 클릭해서 이동할 요소입니다.

입력 → state

const [formData, setFormData] = useState(initialForm);

function handleChange(event) {
  const { name, value } = event.target;
  const nextFormData = { ...formData, [name]: value };
  setFormData(nextFormData);
}

각 input의 name으로 어떤 필드인지 구분합니다. spread는 기존 다른 필드를 보존하고 [name]은 바뀐 필드만 업데이트합니다. 실제 프로젝트에는 제출 후 오류를 다시 검사하는 코드도 있습니다.

제출 → 부모 state → Home

onCapture({ ...formData });
navigate("/");

Contact에서 검사가 통과하면 부모 MainRouter의 state에 데이터를 전달하고 Home으로 이동합니다. Home에서 다섯 필드를 표시해 정보 캡처를 확인할 수 있습니다. useNavigate는 과제의 이동을 구현하기 위해 추가한 기능이며, 교수님의 메뉴 예제와 완전히 동일한 코드는 아닙니다.

이 폼은 실제 이메일을 보내지 않습니다. 데이터베이스·서버 전송·영구 저장은 없습니다. 새로고침하면 캡처한 데이터가 사라집니다. 과제에서 처음부터 완전한 전송 기능을 요구하지 않아 이 방식으로 구현했습니다.

9. GitHub에 업로드하기

GitHub에서 새 저장소를 만들 때 예시 이름은 comp229-react-portfolio입니다. 실제 저장소는 본인 계정에 만듭니다. 현재 프로젝트에 이미 README와 .gitignore가 있으므로 GitHub 생성 화면에서 README/.gitignore/license 자동 추가를 선택하지 않아 빈 원격 저장소로 시작합니다.

교수님이 열람할 수 있는 공개 범위로 설정하세요. 과제 파일 자체가 Public만 요구하지는 않으므로 Private을 쓰는 경우 열람 권한을 따로 확보해야 합니다.

최상위 프로젝트 폴더에서 본인 저장소 주소로 연결합니다. 아래 YOUR-USERNAME과 YOUR-REPOSITORY는 그대로 두는 값이 아닙니다.

git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git remote -v
git push -u origin main

이미 origin이 있는 프로젝트는 git remote -v로 현재 연결을 확인하세요. 인증은 GitHub의 안내를 따르고 비밀번호나 토큰을 코드에 넣지 않습니다. 업로드 후 파일 목록에 client, docs, README 등이 있고 commit 이력이 보이는지 확인합니다. GitHub에는 ZIP 하나만 올리지 않습니다.

10. build → Netlify 배포

다시 client 폴더에서 실행합니다. 이미 client 안이면 cd client를 또 하지 않습니다.

cd client
npm run build
npm run preview

build가 성공하면 client/dist가 생깁니다. preview는 배포용 파일을 로컬에서 확인하는 추가 명령입니다. 그 터미널의 Local 주소로 확인하고 Ctrl+C로 종료합니다.

Netlify에 로그인하고 새 프로젝트의 수동 배포/drag-and-drop 영역에 dist 폴더를 올립니다. 강의 화면의 Add new project 문구는 서비스 화면에서 조금 다르게 보일 수 있습니다. ZIP 전체, src만, client 전체를 올리는 대신 index.html과 assets가 들어 있는 dist를 사용합니다.

client/public/_redirects는 /about 등을 직접 열거나 새로고침할 때 index.html을 제공하도록 추가한 Netlify용 설정입니다.

/* /index.html 200

기존 파일을 유지하고 빌드 결과에도 포함되는지 확인하세요. 이는 모든 주소를 Home 주소로 바꾸는 redirect가 아니라 SPA 화면을 읽게 하는 rewrite입니다. 루트의 netlify.toml은 나중에 GitHub 연결 자동 배포를 할 때 사용할 수 있는 설정입니다. 처음에는 강의의 수동 dist 업로드 흐름만 따라가도 됩니다.

공개 주소가 생기면 같은 테스트를 다시 하고 /about, /project, /education, /services, /contact를 직접 열어 새로고침도 해보세요. localhost는 다른 사람이 볼 공개 주소가 아닙니다.
